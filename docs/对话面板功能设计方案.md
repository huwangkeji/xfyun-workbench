# 对话面板功能设计方案 —— Markdown 渲染 / 点赞差评 / 双模式复制 / 对话分享

> 版本：v1.0（2026-10-25） · 适用范围：`public/index.html` 工作台对话面板
> 约束（继承现有架构原则）：**零新增运行时依赖**（package.json 保持仅 express）、**无构建链**（原生 HTML/CSS/JS）、**最小侵入**（复用 Express + `data/db.json` 存储与现有守卫体系）。

---

## 第一部分 · 需求与总体方案

### 1.1 需求拆解

| # | 需求 | 交互逻辑要点 | 状态管理要点 | 界面布局要点 |
| --- | --- | --- | --- | --- |
| F1 | 对话消息支持 Markdown **渲染**与**还原**展示 | 默认渲染为富文本；每条消息可一键切换回 Markdown 原文（"还原"） | 每消息的视图模式（rendered/source）仅存会话内存，不持久化 | 气泡内双视图切换，工具条提供「原文」开关 |
| F2 | 每条对话提供点赞 / 差评 | 互斥选择；再次点击同一按钮=取消；乐观更新 + 失败回滚 | 评价持久化到消息对象 `feedback`，前端以 `data-fb` 镜像驱动样式 | 工具条内 👍 / 👎 两个图标按钮，选中态高亮 |
| F3 | 复制：纯文本 + 保留 Markdown 两种模式 | 「复制」按钮弹出二选一下拉菜单；剪贴板 API + execCommand 降级 | 无持久状态；复制结果用 toast 反馈 | 工具条「复制」按钮 + 绝对定位下拉菜单 |
| F4 | 分享当前对话 | 聊天头「分享」→ 弹层生成只读快照链接；支持复制链接、再次生成、撤销、过期 | 分享记录存 `db.json.shares`（token + 快照 + 过期时间） | 聊天头按钮 + 模态弹层（链接框 / 有效期 / 分享列表）+ 独立分享页 `/s/:token` |

### 1.2 总体架构

```
浏览器（工作台 index.html + app.js）
  │
  ├─ Markdown 渲染：assets/markdown.js（零依赖，浏览器/Node 双端）
  │     MD.render(md) → HTML（先整体转义，再白名单生成标签，URL 协议白名单）
  │     MD.toPlain(md) → 纯文本（剥离语法，供「复制纯文本」）
  │
  ├─ 消息工具条（每条消息 hover 显示）：复制▾ / 原文 / 👍 / 👎
  │
  └─ fetch API（沿用现有 api() 封装，401 自动跳登录）
        ├─ PUT  /api/conversations/:id/messages/:mid/feedback   评价持久化
        ├─ POST /api/conversations/:id/share                    创建分享（快照）
        ├─ GET  /api/conversations/:id/shares                   分享列表
        ├─ DELETE /api/conversations/:id/shares/:token          撤销分享
        └─ GET  /api/share/:token                               公开读（豁免工作台密码）

Express（server.js）
  ├─ 现有守卫：/api/* 受工作台密码/员工登录保护（本次仅豁免 /api/share/:token 读）
  ├─ conversationService：消息补 id（懒迁移）+ feedback 读写
  ├─ shareService（新）：shares 集合、token 生成、快照（图片内联 data URI）、过期校验
  └─ GET /s/:token → public/share.html（公开只读页，早于静态托管注册）

分享页（share.html + share.js）：渲染快照消息（复用 markdown.js），仅保留复制功能
```

### 1.3 关键设计决策（4 个）

1. **Markdown 渲染器自研而非 CDN/依赖**：工作台跑在 `127.0.0.1` 内网/离线环境，CDN 不可达；项目维持"零依赖"原则。渲染器约 300 行，覆盖聊天场景 95% 语法（标题/列表/表格/代码块/引用/链接/图片/强调/删除线），不做语法高亮（文档化说明）。
2. **"还原展示"= 渲染视图 ⇄ 原文视图逐条切换**：不引入全局开关，避免破坏沉浸阅读；切换态只存内存（`Map<msgId, 'rendered'|'source'>`），刷新即回到默认渲染视图。
3. **分享用"快照"而非"活引用"**：创建分享时把消息（含图片，内联为 data URI）拷贝进 `shares[].snapshot`。源会话后续增删改不影响已发出的链接——符合"分享出去"的语义，也避免分享页读到未授权的新内容。撤销 = 删除记录；过期 = 读时校验 `expiresAt`（默认 30 天，可 7/30/90/永久）。
4. **安全边界**：
   - XSS：渲染器**先对全文 HTML 转义，再生成白名单标签**；链接/图片 URL 过协议白名单（http/https/mailto/锚点/相对路径/`data:image`），`javascript:` 等一律丢弃；
   - 分享 token：`crypto.randomBytes(16).base64url`（22 位，不可猜测，即链接本身的能力凭证）；
   - 分享读接口（`GET /api/share/:token`）与分享页**有意豁免工作台密码**（否则"分享出去"无意义），但创建/列表/撤销仍受现有守卫保护；文档中明确该风险并提供撤销/过期手段；
   - 快照图片内联设 2MB 总量上限，防 db.json 膨胀；上传目录读取用 `path.basename` 防目录穿越。

## 第二部分 · 数据模型与接口设计

### 2.1 数据模型变更（`data/db.json`）

```js
// conversations[].messages[] 新增两个字段
{
  id: "msg_<36进制>",        // 新增：appendMessages 时生成；旧数据由 getFull 懒迁移补齐
  role: "user|assistant",
  content: "..." | [...],    // 不变（多模态数组）
  time: "ISO",
  feedback: null | { value: "up"|"down", at: "ISO" }   // 新增：点赞/差评
}

// 新增顶层集合（db.js DEFAULT_DB 增加 shares: []）
shares: [{
  id: "shr_<36进制>",
  token: "<22位 base64url>",     // 链接凭证：/s/<token>
  convId: "conv_xxx",
  title: "会话标题",
  createdAt: "ISO",
  expiresAt: "ISO|null",         // null=永久
  createdBy: "owner|guest",      // 员工用户名或 guest
  snapshot: {
    title: "快照标题",
    sharedAt: "ISO",
    messageCount: 12,
    messages: [{ role, content, time }]   // 图片已内联为 data URI（≤2MB）
  }
}]
```

### 2.2 接口清单

| 方法 | 路径 | 守卫 | 说明 |
| --- | --- | --- | --- |
| PUT | `/api/conversations/:id/messages/:mid/feedback` | 工作台守卫 | body `{value:'up'|'down'|null}`；互斥更新；返回更新后的消息 |
| POST | `/api/conversations/:id/share` | 工作台守卫 | body `{expiresInDays: 7\|30\|90\|0}`（0=永久，默认 30）；返回 `{token,url,expiresAt,messageCount}` |
| GET | `/api/conversations/:id/shares` | 工作台守卫 | 返回该会话的活跃分享列表（不含快照正文） |
| DELETE | `/api/conversations/:id/shares/:token` | 工作台守卫 | 撤销分享 |
| GET | `/api/share/:token` | **公开** | 返回快照；不存在 404；已过期 410 `SHARE_EXPIRED` |
| GET | `/s/:token` | **公开** | 分享页 HTML（早于静态托管注册） |

错误码约定沿用现有 `{ok:false, error}` 形态。

## 第三部分 · 交互逻辑详设

### 3.1 F1 Markdown 渲染与还原展示

**渲染管线**（`markdown.js`）：

```
原始 md 文本
  → 行级块解析（围栏代码块 → 标题 → 水平线 → 引用 → 表格 → 列表 → 段落）
  → 行内解析（先行内代码占位 → 图片 → 链接 → 粗体/斜体/删除线 → 还原行内代码）
  → HTML 字符串 → innerHTML 写入气泡
```

- 块解析按行扫描，支持：`#`~`######` 标题、``` 围栏代码块（带语言标签）、`>` 引用（可嵌套渲染）、`|` 表格（对齐 `:--`/`:-:`/`--:`）、无序/有序列表（按缩进嵌套一层以上）、`---` 水平线、段落（软换行转 `<br>`，贴合聊天习惯）。
- 安全：进入管线前**整体 HTML 转义**，因此消息里的原始 HTML/`<script>` 只会作为文本显示；URL 白名单过滤后才进 `href/src`。
- 应用时机：历史消息渲染（`renderMessages`）与新回复落库后（`addMsg`）统一走 `MD.render`。错误消息（调用失败）走纯文本 `esc()` 不高亮。

**还原（原文）切换**：

- 每条消息工具条含「原文」按钮（`</>` 图标）：点击在 `渲染视图 / 原文视图` 间切换，按钮 `.active` 表示当前为原文视图。
- DOM 上同时挂两个气泡（`.bubble.md` 与 `.bubble.md-src`），用 `hidden` 属性切换，避免重解析。
- 状态：`msgViews: Map<msgId,'rendered'|'source'>`，仅内存；无 msgId 的极端旧数据退化为 index 键。
- 默认态：渲染视图（内容不含 Markdown 语法时渲染结果与原文一致，无感）。

### 3.2 F2 点赞 / 差评

**状态机**（单消息）：

```
        click 👍(当前=null)          click 👍(当前=up)
null ─────────────────▶ up ──────────────────────▶ null（取消）
 │                        │
 │ click 👎(当前=null)     │ click 👎
 ▼                        ▼
down ◀────────────────── up
        click 👎(当前=up)（直接改判，不经过取消）
```

- 互斥：同一时刻只有一个激活；点相反按钮直接改判。
- 乐观更新：点击立即改 DOM（`data-fb` + 按钮 `.active`）→ `PUT feedback` → 失败回滚并 toast。
- 持久化：`messages[].feedback = {value, at}`；**不更新 `conv.updatedAt`**（避免评价动作把会话顶到侧栏最上）。
- 入口范围：user / assistant 消息均提供（按需求"每条对话"）；调用出错的错误消息只给复制，不给评价。
- 旧数据无 `id`：`getFull` 懒迁移补 id，因此正常路径都能持久化；极端缺失时降级为纯本地切换。

### 3.3 F3 复制（纯文本 / Markdown 双模式）

- 交互：工具条「⧉ 复制」按钮 → 下拉菜单二选一：
  - **复制纯文本**：`MD.toPlain(raw)`——剥离 `#`、`*`、`[]()`、表格竖线转 ` | ` 等，代码块内容保留；
  - **复制 Markdown**：消息原始文本原样复制（保留全部语法，便于贴到别的 Markdown 编辑器）。
- 剪贴板：优先 `navigator.clipboard.writeText`（127.0.0.1 属安全上下文，可用）；失败降级隐藏 textarea + `document.execCommand('copy')`；两者都失败 toast 提示手动复制。
- 反馈：toast「已复制纯文本 / 已复制 Markdown」；空文本消息 toast「该消息没有文本内容」。
- 菜单开合：点击按钮开；点击菜单项执行并关；点击页面其他区域/ Esc 关（document 级监听）。

### 3.4 F4 分享当前对话

**创建流程**：

```
聊天头「🔗 分享」→ 前置校验（无会话/无消息 → toast 拦截）
  → 弹层：有效期选择（7天/30天/90天/永久，默认30天）+「生成分享链接」
  → POST /share → 快照落库 → 链接框只读展示 +「复制链接」+ 列表刷新
```

**查看流程**：任何人打开 `http://127.0.0.1:4000/s/<token>` → `share.html` → `GET /api/share/:token` → 渲染快照（标题/分享时间/条数/消息列表，Markdown 渲染，只读，仅保留复制按钮）；404/410 → 友好错误卡（"链接不存在或已被撤销 / 已过期"）。

**管理流程**：弹层内「已创建的分享」列表展示该会话所有活跃分享（token 缩写、创建时间、过期时间、消息数），支持单条「撤销」（DELETE）与「复制」。

**过期与撤销**：读时校验 `expiresAt`（过期即 410，页面提示过期）；撤销即删记录（404）。不做后台清扫任务（读时过滤足够，数据量小）。

## 第四部分 · 状态管理与界面布局

### 4.1 前端状态（app.js 新增，集中在现有模块尾部）

```js
const msgState = {
  views: new Map(),    // msgId → 'rendered' | 'source'（仅内存）
  fbPending: new Set() // 正在提交评价的 msgId（防连点）
};
// 消息节点上以 dataset 承载即时状态：data-mid / data-fb（'' | 'up' | 'down'）
// 权威状态以服务端为准：currentConv.messages[].feedback，渲染时初始化 dataset
```

持久化分工：**评价/分享 → 服务端 db.json**；**视图切换/剪贴板 → 仅前端**；**无 localStorage 新增**（复制、查看不需要跨会话记忆）。

### 4.2 消息 DOM 结构（布局核心）

```html
<div class="msg assistant" data-mid="msg_xxx" data-fb="">

      <div class="copy-group">

- 触屏设备（`@media (hover:none)`）工具条常显（降透明度）。

### 4.3 分享弹层与分享页布局

- **弹层**（index.html 内 `.modal-mask#shareModal`）：标题栏 + 提示语 + 有效期 select + 生成按钮 + 链接框（只读 input + 复制按钮）+ 「已创建的分享」列表（行：token 缩写 · 创建时间 · 过期 · 条数 · 复制/撤销）。
- **聊天头**：状态行右侧新增「🔗 分享」按钮（`.btn.btn-sm`）。
- **分享页**（share.html）：复用 topbar 品牌样式；主体为居中卡片（标题 / 元信息 / 消息流，消息流复用 `.msg` 体系但去掉工具条中的评价按钮，仅保留复制）；底部"由 星火工作台 分享 · 只读"。

### 4.4 样式约定

- 全部复用 `style.css` CSS 变量（`--accent/--danger/--panel/--border` 等），不引入新色板。
- Markdown 内容样式挂在 `.bubble.md` 作用域内（标题层级、列表缩进、`pre` 代码块底色、表格细边框、引用左边框），避免污染全局。
- 点赞激活态：`--accent` 蓝；差评激活态：`--danger` 红。

## 第五部分 · 边界、异常与验收

### 5.1 边界与异常

| 场景 | 行为 |
| --- | --- |
| 会话无消息时点分享 | toast 拦截，不创建分享 |
| 分享的会话含图片 | 图片内联 data URI（≤2MB）；超限保留 `/uploads` 相对 URL（开启访客密码时公页面可能不显示，属可接受降级） |
| 分享后源会话继续对话 | 快照不变（设计语义） |
| token 不存在 / 已撤销 | 404，分享页显示"链接不存在或已被撤销" |
| 链接过期 | 410 `SHARE_EXPIRED`，分享页显示"链接已过期" |
| 工作台开启访客密码 | 创建/列表/撤销需登录；`/s/:token` 与 `GET /api/share/:token` 豁免（token 即凭证） |
| 剪贴板 API 被拒（非安全上下文/权限） | execCommand 降级 → 再失败 toast 提示手动复制 |
| 评价接口失败 | 回滚 UI + toast，不丢消息 |
| 旧消息无 id | getFull 懒迁移补 id 并落盘（一次性） |
| 消息含原始 HTML/脚本 | 转义后当文本显示；URL 白名单外协议丢弃 |

### 5.2 验收清单

- [ ] Markdown：标题/列表/表格/代码块/引用/链接/图片/粗斜体/删除线渲染正确；`<script>alert(1)</script>` 原样显示不执行；`[x](javascript:...)` 链接被降级为纯文本
- [ ] 还原：每条消息可切换原文/渲染，刷新后回到渲染视图
- [ ] 评价：点赞/差评互斥、再点取消、失败回滚；刷新后状态保持（db.json 有记录）
- [ ] 复制：两种模式内容正确（纯文本无语法符号；Markdown 保留原文）；toast 反馈
- [ ] 分享：生成链接 → 新开 `/s/:token` 只读渲染 → 撤销后 404 → 过期后 410；源会话改动不影响快照
- [ ] 兼容：旧会话（无 id/feedback 字段）正常加载并自动补 id；访客密码开启时分享创建需登录、分享页可匿名访问

### 5.3 后续可选增强（本期不做）

- 代码块语法高亮（引入会破坏零依赖，可做按需懒加载）
- 分享页二维码（需引入二维码库，违背零依赖）
- 后台「记忆管理」展示消息评价分布（admin.js 增量）
- 分享访问计数/最晚访问时间

| --- | --- |
| 身份注入 | `server.js` 对 `/api/conversations` 挂载 `attachTeamUser`：携带有效员工会话 → `req.user`；否则按访客 |
| 评价端点 | `PUT /:id/messages/:mid/feedback` → `setFeedback(id, mid, value, viewer)`，先过会话可见范围，范围外 404（视同不存在，不泄露存在性） |
| 分享创建/列表/撤销 | 同样先 `getFull(id, req.user)` 范围校验，再走 `shareService`（内部用 `getFullAny`） |
| 可见范围 | owner/admin 全部；member/viewer 仅 `ownerId` 为自己；**访客仅 `ownerId` 为空的"访客桶"** |
| 公开读 | `GET /api/share/:token` 与 `/s/:token` 仍豁免（token 即凭证，与角色体系无关） |
| 数据迁移 | `bootstrapMigrate()` 每次启动把无 `ownerId` 的会话打标给 owner；`migrateIds()` 给缺 id 的旧消息补 id（懒迁移，评价/分享依赖） |

**已知交互（属并行改造范围，非本方案引入）**：访客在会话中产生的 `ownerId=null` 会话，会在下次服务重启时被 `bootstrapMigrate` 打标为 owner 归属，访客侧列表随即不再显示（前端侧栏的 RBAC 适配由该改造负责）。本方案的前端在 404 场景下统一 toast 报错，不静默失败。

**兼容性结论**：本方案全部功能在上述 RBAC 层下按设计工作——访客桶内会话的渲染/评价/复制/分享全流程已验证通过（见 5.2 验收清单的实测记录）。
