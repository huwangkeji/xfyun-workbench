# 2026-10-25 星火 MaaS 工作台修复「调用失败: Failed to fetch」

## 根因（两个叠加 bug）
1. **进程崩溃（主因）**：`src/routes/chat.js` 显式配置分支取 `callResult.result`，但 `xfyun.chatCompletions()` 返回体字段是 `.data` 没有 `.result` → `result` 恒为 null → 成功路径 `extractResult(result.data)` 抛 TypeError。express 4 不捕获 async 路由异常 → unhandledRejection 直接杀掉 node 进程 → 浏览器所有请求 "Failed to fetch"（聊天+保存消息全挂）。日志证据：13:52:51 服务端 ok 但响应没回到浏览器。
2. **回复为空**：`configService.optInt(null/'' )` 中 `Number(null)===0` 被钳到下限，maxTokens 恒为 1，模型只能生成 1 token 全被思考过程占用，正文永远空。

## 修复清单
- `chat.js`：结果体归一化 `callResult.result || (callResult.status !== undefined ? callResult : null)`；路由包 asyncHandler
- 新增 `src/asyncHandler.js`；chat/config/image/network 全部 5 个 async 路由包装（闭合改 `}));`）

### 踩坑链条（按顺序）
1. **域名栏不能填 `IP:端口`** —— 面板域名栏只接受域名/IP，端口在上面单独填。填 `139.129.23.133:4000` 非法
2. **80 端口已被其他站占用**（该服务器上已有「改写宝」站点）→ 不能用裸 IP 做域名，必须用独立子域名才能共存
3. **EACCES 权限错误（真正的启动失败原因）**：面板用 www 用户启动 Node，但上传的文件属主是 root → `data/db.json` 无法写入 → adminAuth.bootstrap() 崩溃。
   解决：`chown -R www:www /xp/www/xfyun-workbench` + `chmod 775 .../data`（或面板里把运行用户改成 root）
4. **nginx 400 Request Header Or Cookie Too Large（假象）**：Node 没起来时 4000 无人监听，面板的 nginx 反代指向 4000 自己形成自循环，任何请求都返回 400。**这个错误是"服务没起来"的表象，不是 nginx 配置问题**——不要被误导去改 nginx

### 诊断方法（有效）
从外部 curl 探测：`curl -o /dev/null -w "%{http_code}" http://IP:4000/` + `/api/health`。
- 000=端口不通（安全组未放行）
- 400 Cookie Too Large=nginx 自循环，说明 Node 没起来
- 200 + title 含「星火工作台」= 成功

- 面板勾选端口「放行」只管服务器本机防火墙，**阿里云 ECS 安全组是独立一层**，需要单独放行
