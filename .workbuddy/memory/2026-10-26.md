# 2026-10-26 修复管理员登录 / 员工端退出登录 + 密码重置工具

## 根因与修复

### 1. 员工端无法退出登录（已复现 + 已修复）
- **根因**：`src/adminAuth.js` 的 `setCookie/clearCookie` 用 `res.setHeader('Set-Cookie', ...)`，而 setHeader 是**替换**语义。退出登录路由先 `clearTeamCookie` 再 `clearCookie`，第二条把第一条整条覆盖 → 响应里只剩 `admin_token=; Max-Age=0`，**team_token 原样保留**。实测：退出后 /me 仍 200、/team-login 被守卫 302 弹回 /app、/admin 仍可进——"退了等于没退"。
- **修复**：新增 `appendCookie()`（优先 `res.append`，兜底数组式 setHeader）；新增 `clearAllAuthCookies(res)` 一次性清除 team_token/admin_token/wb_token；`/api/auth/logout`、`/api/admin/logout`、`PUT /api/auth/password` 全部改走它。
- **验证**：退出响应三条 Set-Cookie 齐全；jar 清空；/me 401；/team-login 200；/admin 302→/team-login?next=/admin。

### 2. 管理员无法登录（登录链路审计 + 修复）
- 登录接口本身用正确密码可登（curl 实测），真正的坑是**登录后跳转丢失**：3.0 提交把登录成功一律 `location.replace('/app')`，从 /admin、/admin/login 进来的管理员被扔到工作台，找不到后台。
- **修复**：
  - `team-login.html`：`safeNext()`——`?next=` 优先（仅放行本站本地路径，防 `//evil.com`、`/\`、循环），否则按 Referer 推断，回退 /app；
  - `server.js`：`/admin/login` 未登录 → 302 `/team-login?next=/admin`；`/team-login` 已登录按 next 跳；
  - `adminAuth.requireTeamPage`：未登录带 `next=originalUrl` 跳登录页；
  - app.js/me.js/admin.js 的 401 分支带 `next=location.pathname`。
- **限流可感知**：IP 锁/账号锁错误信息改为动态剩余秒数（`lockRemainSec`/`userLockRemainSec`），如「该账号失败次数过多，请 300 秒后再试」。
- **安全加固**：`userService.update` 新增 `patch.password`（指定密码， bump passwordUpdatedAt 失效旧会话）；`routes/admin-users.js` 把 `password` 列入自操作保护——否则成员管理接口会成为跳过旧密码校验的改密旁路。

### 3. 密码重置文件（新增）
- `scripts/reset-password.js`：零依赖直写 db.json（走 userService.update，原子写 + 令牌失效语义一致）。
  - `node scripts/reset-password.js` → owner 随机临时密码（默认强制改密）
  - `node scripts/reset-password.js <user> --password 新密码 [--no-force-change]`
  - `--list` 只看列表；弱密码拒；不存在账号拒并列出现有账号
  - 打印后续步骤：重启服务（内存缓存覆盖 + 重启才解限流锁定）→ /team-login 登录
- `重置密码.bat`：chcp 65001 + `node scripts\reset-password.js %*` + pause，双击可用。

## 追加：重置密码被运行中服务覆盖事故（用户截图反馈）→ 工具加固

### 事故还原
用户双击 重置密码.bat 重置 owner 成功（新密码 2PB-zeyBhWtc），但**服务仍在运行**，未按提示重启；运行中进程的内存缓存把 db.json 覆盖回旧密码（只读体检证实：磁盘 passwordUpdatedAt 仍是 10-25 原值，新密码验证 false）。用户拿新密码登录 → "用户名或密码错误"。另：cmd 窗口出现乱码命令错误——两个 bat 都是 **LF 换行**（cmd.exe 要 CRLF）+ bat 内含中文，用户又在系统 cmd 里手打中文命令（代码页不匹配）。

### 加固（scripts/reset-password.js）
- **服务运行检测**：net.connect 探 127.0.0.1:PORT（PORT 读 env/.env，默认 4000）→ 探到就**拒绝重置**并打印四步操作（关服→重跑→重启→登录），exit 1；`--force` 可强行重置
- **落库校验**：重置后重读 db.json 文件 + verifyPassword 确认新密码真的写进去了（防静默失败/文件占用）
- 输出增加「已通过落库校验」字样

### bat 修复
- 重置密码.bat 重写为 **CRLF + 纯 ASCII**（中文输出全部交给 Node——实测 chcp 65001 下 Node 的 UTF-8 中文输出正常，用户截图已证）；启动.bat 同步 LF→CRLF（内容不动）
- 教训：**Write 工具写出的文件是 LF**，.bat/.ps1/.cmd 在 Windows 上必须 CRLF；写完后用 `cat -A` 验 `^M$`；另注意 node -e 里反斜杠被 bash 吃了（`scripts\\reset` 变 `scripts\r`）——写 Windows 路径优先用 Write 工具 + sed 转 CRLF

### 验证（隔离环境 PORT=4125）
服务在跑→拒绝且数据零改动；--force→放行；停服→重置+落库校验通过；完整恢复流（停服→重置→重启→登录 200→/admin 200→退出→302 回登录页）全过；npm test 12/12

### 分享 bug 根因（重点）
- **现象**：开启了访客密码时，公开分享页 `/s/:token` 里的上传图片裂图
- **根因**：`shareService` 内联图片用 `path.basename(url)`，而 URL 是 `/uploads/2026-10-26/img_x.png`（带日期子目录）→ basename 剥成 `img_x.png` → 拼出 `public/uploads/img_x.png` 不存在 → readFileSync 失败被吞 → 静默保留外链 → 匿名访客既拿不到 /uploads 直链（401）又没内联 → 裂图
- **修复**：新增 `resolveUploadPath(url)` 保留完整相对路径 + `path.resolve` 前缀校验（防目录穿越），内联失败才回退外链；测试覆盖 data URI 内联成功 + 恶意 URL 拒绝 + 过期撤销
